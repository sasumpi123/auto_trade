# 실제 업비트 과거 데이터 연구

이 경로는 공개 시세 GET만 사용합니다. 계정, 주문, 인증키 또는 기존 운영 봇을 사용하지 않습니다. 실제 주문과 운영 배포는 금지하며 REAL_TRADING=False를 유지합니다. 기존 운영 전략을 교체하지 않습니다.

## 사전 고정한 실험

`backtesting/protocol.json`을 결과 수집 전에 별도 커밋으로 고정합니다. 기간은 UTC 봉 시작 시각의 반열린 구간입니다.

| 구간 | 시작 포함 | 끝 제외 | 용도 |
|---|---|---|---|
| 학습 | 2026-07-23 00:00 | 2026-09-15 00:00 | 고정된 후보의 개발 구간 성과 보고 |
| 검증 | 2026-09-15 00:00 | 2026-10-03 00:00 | 독립 시간 구간 결과 보고; 튜닝/선택 없음 |
| 미사용 테스트 | 2026-10-03 00:00 | 2026-10-21 00:00 | 전략 평가·지표 계산에 넣지 않음 |

이는 확보 가능한 전체 역사 중 최근 완료된 90일의 초기 연구입니다. 학습 알고리즘이나 최적화는 없으며 54/18/18일 분리를 적용합니다. 90일만으로 장기 수익성, 다양한 시장 국면, 통계적 유의성을 주장하지 않습니다. 날짜를 수익률에 따라 바꾸지 않습니다. 미사용 테스트도 품질/해시 검사는 하지만 손익을 계산하지 않습니다. 이번 성과는 학습·검증 결과이며 미사용 테스트 성과는 공개하지 않습니다. 검증 결과를 열어 본 이후 이 구간은 향후 모델 변경의 최종 독립 검증으로 재사용하면 안 됩니다.

## 확보 가능 기간과 품질

- BTC/ETH/XRP/SOL의 KRW 마켓과 15분/60분만 허용합니다. 인증 없는 고정 `https://api.upbit.com/v1/candles/minutes/{unit}`에 GET하고 리다이렉트는 거부합니다. 환경 인증·프록시 사용도 비활성화합니다.
- 최대 200개, 배타적 `to` 커서를 가장 오래된 봉 시작 시각으로 이동합니다. 응답 마켓/단위/시간 정렬/중복/그리드를 검사합니다. 429·일시적 5xx·네트워크 오류는 제한 횟수 재시도하며 그 외 HTTP 오류는 중단합니다. 호출 간 0.26초 대기하며 공유 IP 제한도 영향을 줄 수 있습니다.
- 2017-01-01 이전 빈 응답에서 시작해 UTC 날짜 단위 이진 존재 탐색 후 첫날 응답으로 가장 이른 **실제 관측 가능 봉**을 확인합니다. 이는 최초 상장일 또는 모든 과거 구간의 완전성을 증명하지 않습니다. 최신 관측값도 고정한 연구 종료 시각 이전 기준입니다.
- OHLCV 유한성·양수 가격·OHLC 경계·음수 거래량·중복·순서·캔들 간격·앞뒤 누락을 검사합니다. 단일 봉 20% 초과 변동은 완전한 구간에서 진단 수치로 남기며 가격에 근거해 표본을 제거하지 않습니다.
- 누락 봉은 원본 그대로 남기고 전체 창을 품질 부적합으로 표시합니다. **자동 bfill/ffill, 가격 보간, 조용한 중복 제거를 하지 않습니다.** 공개 API는 거래가 없는 구간에 봉을 생성하지 않을 수 있으므로 누락이 수집 오류인지, 무거래/거래소 중단인지 데이터만으로 단정하지 않습니다.
- 학습+검증 접두 구간을 별도로 엄격 검사합니다. 미사용 테스트에만 누락이 있으면 그 구간을 부적합으로 격리하고 완전한 학습·검증만 평가할 수 있습니다. 개발 구간 누락은 전체 실행을 실패시킵니다. 테스트의 향후 사용 전 원인 조사 및 새 독립 표본 설계가 필요합니다.
- 정규화 CSV gzip 스냅샷, 파일 SHA-256, 정규화 데이터 SHA-256, 요청 URL/파라미터/응답 해시/서버 일자/수집 시각, 구간별 해시를 보존합니다. JSON 원문 응답 전체는 보관하지 않으며 응답 해시는 요청 감사 기록입니다. 재수집 시 과거 봉이 수정될 수 있으므로 보고된 결과 재현에는 PR의 고정 스냅샷을 사용합니다.

## 동일 조건 비교와 기준선

RSI, MACD, 볼린저 단독, E5 반대 표 없는 2/3 합의, 3/3 합의, 기존 신호 호환 전략을 모두 평가합니다. `legacy_composite`도 **신호 계층의 비교**이지 운영 봇 전체 손익이 아닙니다. 손절·익절·물타기 오버레이와 다종목 자금 경합은 모사하지 않습니다.

각 종목·봉 주기·구간은 독립 초기 자금 1,000,000원에서 시작하며 전략은 40% 고정 노출 한도입니다. 검증 시작 시 현금과 포지션을 초기화하고 학습 거래는 넘기지 않습니다. 대신 그때까지의 학습 봉을 지표 계산 문맥으로만 사용합니다. 지표 워밍업은 기존 연구 엔진과 동일하며 순방향 계산만 허용합니다. 준비된 지표/스냅샷을 비용 조합 간 재사용하여 계산량을 줄이며 데이터/지표를 변경하지 않습니다.

완료 봉에서 신호 → 다음 봉 시가에 실행합니다. 쿨다운 300초, 거래량 평균의 0.5배 필터, 최소 5,000원, 소수 8자리 수량 내림, 무차입, 동시 1포지션을 적용합니다. 같은 거래량 필터가 신호 전략의 매수/매도를 막을 수 있습니다.

보유 기준선은 `buy_hold_40`(동일 40% 노출)과 `buy_hold_100`(일반적인 100% 노출)을 **구분**합니다. 공통 지표 워밍업이 끝난 첫 완료 봉 다음 시가에서 한 번 매수하고 끝까지 보유합니다. 검증에서는 첫 검증 봉이 완료된 다음 봉에서 매수합니다. 수수료·슬리피지·스프레드·수량 내림 규칙은 같습니다. 보유 기준선은 지표 신호나 거래량 비율 필터를 쓰지 않으나 0거래량 봉에서는 실행 신호를 내지 않는 엔진 정책을 유지합니다. 실제 스냅샷 개발 구간에 0거래량 봉이 있는지 품질 보고서를 확인합니다. 100% 기준선과 40% 신호 전략을 동일 위험 노출의 우열로 해석하지 않습니다.

## 비용 민감도와 지표

- 편도 수수료 5/10bps × 편도 슬리피지 0/5/10bps의 **6조합 전부**를 보고합니다. 전체 스프레드 2bps의 반을 매수·매도 각각 적용합니다. 기본 표시 조건은 수수료 5bps·슬리피지 5bps이며 사전 고정한 값이지 최적값이 아닙니다. 실제 업비트 계정 요율·호가를 검증한 값이 아닙니다.
- 순수익률은 시작 현금 대비 마지막 종가 평가 자산 증감률, MDD는 초기 자금부터 매 봉 종가 평가 기준 낙폭입니다. 실제 장중 최대 손실은 아닙니다.
- 승률은 **수수료 포함 실현손익이 양수인 종료 왕복 거래 / 종료 왕복 거래**입니다. 종료 거래가 없으면 null/해당 없음이며 0%가 아닙니다. `closed_trades`는 종료 왕복 횟수, `fill_count`는 매수+매도 체결 수로 각각 표시합니다.
- 마지막 보유분은 강제 청산하지 않으며 향후 청산 비용이 제외됩니다. 보유 기준선은 종료 왕복 거래가 없으므로 승률이 없습니다. 마지막 봉 신호도 미체결 상태이며 이익으로 계산하지 않습니다.
- 최적 전략·파라미터 선택, 탐색, 결과 기반 조기 종료를 하지 않습니다. 모든 구간·종목·비용 결과를 CSV/JSON으로 공개합니다. 여러 후보·구간을 열어 보는 다중 비교 자체가 연구 편향을 유발할 수 있으므로 후속 변경에는 새 미사용 표본이 필요합니다.

## 재현

```bash
python -m backtesting.historical collect --data runtime/new-snapshot
python -m backtesting.historical evaluate --data runtime/new-snapshot --output runtime/new-results
# PR에 보존된 스냅샷으로 같은 결과 재현 (기존 출력 디렉터리 사용 금지)
python -m backtesting.historical evaluate --data research/2026-10-21/data --output runtime/reproduced
python -m unittest discover -v
```

CI는 네트워크를 사용하지 않는 가짜 공개 응답과 합성 데이터로 수집·시간 분리·봉인 테스트·비용·기준선을 검증합니다. 실제 데이터 스냅샷/품질 및 재현 결과도 별도 검사합니다. 실제 API 호출은 이번 수동 수집 경로에서만 수행했습니다. 실거래 주문, 계정 API, 운영 배포는 수행하지 않았습니다.

공식 문서: [분 캔들](https://docs.upbit.com/kr/reference/list-candles-minutes), [과거 캔들 수집 안내](https://docs.upbit.com/kr/docs/how-to-download-candle-data). 후속 연구: #7, 비용 모델 #5, 운영 bfill #4.

프로토콜 해시는 UTF-8 텍스트 개행을 LF로 정규화한 뒤 계산합니다. Windows Git checkout의 CRLF 변환은 실험 내용 변경으로 취급하지 않으며, 공백·필드·값 변경은 여전히 해시 불일치로 차단합니다.
