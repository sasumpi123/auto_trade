# P34 한 PAPER 계좌, 두 종목 동시 하락 시 노출·현금·손절 경로 검산

이슈 #73. 상위 위험 검토 #3(종목당 40%와 계좌 노출)과 #2(1회 물타기)에 속한 하위 작업입니다.

- P11 위험 연구는 종목마다 계좌를 따로 둔 비교였습니다. 이번 검산은 시작 현금 100만 원인 **같은 계좌**에서 두 종목이 함께 하락할 때를 다룹니다.
- 확인하는 항목은 현금, 노출, 물타기, 손절이 실제로 어떻게 처리되는지입니다.
- 계좌 단위 한도를 정할 근거로 쓰기 위한 작업이며, **새 한도나 정책은 적용하지 않습니다.**

## 재현 (오프라인, 한 명령)

```bash
PYTHON_DOTENV_DISABLED=1 .venv/bin/python -m backtesting.p34_shared_cash --output "$HOME/research/p34-$(date +%Y%m%d-%H%M%S)"
```

- 출력은 `results.json`(단계별 전후 상태, 주문, P9 대사)과 `steps.csv`입니다.
- 표준출력은 최대 8줄입니다.
- 네트워크 호출, 기존·실계좌 접근, P19/P22/P33 자료 사용은 모두 없습니다.
- 실행마다 새 임시 계좌를 만듭니다.

## 실제로 호출하는 경로

- **봇:** `trading.auto_trade.AutoTrade`를 수정 없이 사용합니다.
  - 위험 판단 순서: 익절 +5%, 그다음 −5%에서 1회 50% 물타기, 실패하거나 이미 썼으면 손절.
  - `MAX_COINS_AT_ONCE=2`, 종목당 `max_per_coin` 40만 원(40%), 최소주문.
- **체결 엔진:** 일회용 연구 P17 엔진(`P17ResearchEngine`)입니다. 비용은 5/5/2bps이고, 수수료를 포함한 예산 안에서 체결하며, 실제 PAPER 체결·원장 경로를 거칩니다.
- **원장 대사:** P9 `services.notification_metrics.replay`로 재생해 현금, 수수료, 수량, 순실현 손익과 equity 항등식을 대조합니다. 하나라도 어긋나면 `P34_P9_*`로 중단합니다.
- **합성 부분:** 첫 진입 BUY 신호 하나만 합성합니다. 그 뒤의 물타기·손절·익절 결정은 모두 봇이 직접 내립니다. 계산표나 가짜 체결 함수로 대신하지 않습니다.
- **입력값:**
  - 진입가: BTC 1억 원, XRP 1,000원(합성)
  - 같은 시점의 하락을 두 순서(BTC 먼저 / XRP 먼저)로 처리합니다.
  - 이미 비용이 차감된 현금에서 비용을 다시 빼지 않습니다(P9 항등식으로 검증).

**관찰 (현재 정책의 실제 동작):**

1. **진입 후:** 각 종목에 수수료 포함 40만 원씩 들어가 현금은 200,000원이 남습니다. 총 노출은 마크 기준 약 80%입니다.
2. **동시 −5.5%:** 먼저 처리된 종목만 1회 물타기를 합니다. 금액은 현재 평가액의 50%로 약 188,800원이고, 수수료를 포함합니다.
   - 이후 현금은 약 11,208원이고 총 노출은 약 98.9%입니다.
3. **두 번째 종목:** 물타기 요청액(약 188,800원)이 남은 현금보다 큽니다. 엔진은 이 요청을 정상 거절하고(`value > cash` → `False`, intent·체결 없음), 봇은 같은 tick에서 **즉시 손절**합니다.
   - 즉 현금이 부족하면 "물타기 대신 손절"이 일어나고, **어느 종목이 손절될지는 처리 순서가 결정합니다.**
4. **갭 하락:** −15% 갭에서는 손절이 −5% 선보다 훨씬 아래에서 체결됩니다. 손절선이 손실 상한을 보장하지 않습니다.
5. **물타기 이후:** 손절선이 새 평균가의 −5%가 되므로, −10%로 반등해도 손절됩니다.
6. **처리 순서와 손익:**
   - 대칭 경로에서는 순서가 바꾸는 것이 "어느 종목"뿐이고 총손익은 같습니다.
   - 비대칭 경로에서는 같은 가격이라도 순서에 따라 손익이 −12,502원과 −73,007원으로 달라집니다.
   - BTC 먼저인 경우 BTC가 종료 시점까지 보유로 남습니다.
7. **이론상 최대손실:** 가장 많이 투입된 순간(현금 약 11,208원)에 보유분이 모두 0이 되면 계좌 손실은 약 **988,792원**입니다. 위 표의 합성 실현·평가 손실과는 다른 값입니다.

## 현재 정책의 노출 (사실)과 향후 한도 항목 (사용자 결정)

**현재 정책의 노출 (사실):**
- 종목당 진입 40%
- 동시 보유 최대 2종목
- 1회 물타기는 현재 평가액의 50%
- 계좌 단위 노출 상한이나 물타기용 현금 예약은 없습니다.
- 그 결과 물타기 후 계좌 노출이 98%를 넘을 수 있습니다.

**향후 사용자가 정할 수 있는 항목 (이번 PR에서는 적용하지 않음):**
- 계좌 전체 노출 상한(예: 평가 포지션 합 / equity)
- 물타기용 현금 예약 여부와 규모
- 현금이 부족할 때 손절할지, 보유를 유지할지에 대한 명시적 규칙
- 동시 하락 시 종목 처리 순서 규칙
- 계좌 단위 최대 손실 한도
- 갭 손실에 대한 별도 상한

## 미검증 범위

- 고정 합성 가격만 사용했습니다. 실제 시장 경로, 슬리피지 분포, 호가 깊이, 동시 체결 경합은 다루지 않았습니다.
- 실시간 스트림 tick 순서는 다루지 않았습니다. 순서는 두 가지로 고정했습니다.
- 익절 경로는 이 하락 시나리오들에서 발생하지 않았습니다.
- 수치는 합성 결과이며 수익성이나 위험을 예측하지 않습니다.
- `REAL_TRADING=False`이며 추가 지출은 0원입니다. P33 고정본·등록·수집과 실제 PAPER 계좌는 건드리지 않았습니다.
