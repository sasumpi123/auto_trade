# P0 실행 안전성 변경

기본값은 `config.py`의 `REAL_TRADING = False`입니다. 환경변수로 실거래를 켜지 않습니다.
이번 변경의 테스트는 네트워크 소켓 연결을 차단하고 모든 주문·계좌·시세 응답을 가짜 객체로 제공했습니다.
실제 업비트 주문이나 인증 계좌 조회는 수행하지 않았습니다.

## 전략 보존 범위

- RSI/MACD/볼린저 신호 조건, 조건 평가 순서, 거래량 필터, 5분 쿨다운은 유지합니다.
- 기존 `process_market_data()`의 +5% 익절과 -5% 보호 경로를 실행 루프에 연결합니다.
- 기존 손절 함수는 -5%에서 보유 평가액의 50%를 한 번 물타기하고, 이후 평균단가 대비
  다시 -5%에 도달하면 매도합니다. 물타기 금액이 최소금액/잔고 조건을 충족하지 않으면 매도합니다.
  "첫 -5%에서 무조건 손절"로 전략을 바꾸지 않았습니다.
- 물타기 수량은 기존 수량에 합산하고 평균단가는 체결대금으로 가중평균합니다.
- 분석기가 반환하는 3%/5%/BB `target_price`는 기존처럼 신호 메타데이터입니다.
  새 전략별 목표가 청산 규칙을 추가하지 않았으며 보호 익절 기준은 기존 코드의 고정 +5%입니다.
- 가격 보호는 거래량 필터·신호 쿨다운에 가로막히지 않으며, 틱당 최대 한 번만 주문합니다.
- 상태 보고는 `analyze()`를 호출하지 않아 신호와 쿨다운을 소모하지 않습니다.

## 실행과 복구

1. `runtime/paper-state.json` 또는 `runtime/real-state.json`에 현금, 수량, 평균단가,
   물타기 여부, 신호 시각, 주문 식별자와 체결 내역을 저장합니다. API 비밀키는 저장하지 않습니다.
2. 같은 상태 파일을 사용하는 프로세스는 OS 파일 잠금으로 하나만 실행됩니다.
   임의로 다른 경로를 지정하거나 저장소를 복제해 같은 계좌의 봇을 중복 운영하지 마세요.
3. 주문 의도를 원자적 파일 교체와 fsync로 저장한 다음 한 번만 제출합니다.
   응답 유실, HTTP 오류, UUID 미확인, 체결 대기 시간 초과 시 재제출하지 않고 중단합니다.
4. 실거래 경로는 UUID/identifier로 주문을 조회해 `done`/`cancel`을 확인하고
   `executed_volume`, `trades[].funds`, `paid_fee`를 검증합니다. `price=null`을 체결대금으로 사용하지 않습니다.
   취소된 주문의 부분 체결도 실제 체결분만 반영합니다.
5. 재시작 복구는 조회만 합니다. 저장된 미확정 주문부터 대조하고 계좌 전체 잔고와
   미체결/예약 주문을 확인합니다. 체결 내역과 잔고가 불일치하면 주문 기록을 미확정 상태로 유지하고 중단합니다.
6. 모르는 미체결 주문은 자동 취소하거나 새 주문으로 덮어쓰지 않습니다. 시작을 중단해 사람이 확인하도록 합니다.
   잠금 자산만 보이고 주문이 보이지 않는 불일치도 중단합니다.
7. 상위 10종목 밖의 기존 KRW 현물도 감시 목록에 추가합니다. 과거 물타기 이력이 없는 외부 보유분은
   추가 물타기를 허용하지 않습니다. 비KRW 자산이나 평균단가를 확인할 수 없는 자산은 수동 대조가 필요합니다.
8. 모의매매는 외부 계좌를 읽지 않고 자체 현금/보유 상태를 복구합니다. 모의/실거래 상태 파일이나
   API 계정 식별자가 섞이면 시작하지 않습니다. 손상된 파일은 빈 상태로 덮어쓰지 않습니다.

## 중단 후 처리

- 예외 시 새 주문을 막고 루프를 끝내며 종료코드 1을 반환합니다. 자동 재시작/재주문하지 않습니다.
- 중단은 포지션 자동 청산이나 서버 주문 자동 취소를 뜻하지 않습니다. 보호 주문도 더 이상 실행되지 않습니다.
- `halt_reason`과 저장된 주문을 확인하고 거래소의 실제 주문/잔고와 대조한 뒤 명시적으로 재시작하세요.
  재시작 시 다시 대조하여 정상 상태가 확인된 경우에만 실행을 허용합니다.
- identifier로도 주문을 확인하지 못하면 미확정 기록을 유지한 채 중단합니다. 파일을 삭제해 우회하면
  중복 주문 위험이 생깁니다. 미확정 기록의 수동 처리는 실제 거래소 상태 확인과 백업 이후에만 해야 합니다.
- `runtime/`와 `.lock` 파일을 실행 중 삭제하지 마세요. 상태 파일은 재시작 시 계속 사용해야 합니다.
- WebSocket 수신은 15초로 제한되며 단절/오류 시 멈춥니다. SIGINT/SIGTERM은 진행 중 주문 대조를
  마친 후 정상 정리하도록 요청합니다. 최대 대기시간은 HTTP 타임아웃과 조회 횟수에 의해 제한됩니다.

## 테스트

Python 3.12 가상환경에서 저장소 루트 기준으로 실행합니다.

```bash
python -m pip install -r requirement.txt
python -m unittest discover -s tests -v
```

검사 대상: 가격 보호 경계, 전략 신호 회귀, 중복/동시 주문, 프로세스 잠금, 지연/부분/취소 체결,
응답 유실, 체결 후 저장 전 장애, 미확정 주문 복구, 오래된 계좌 응답, 상태 파일 손상,
계정/모드 혼용, 데이터/저장소/알림/연결 오류와 중단 후 주문 차단.

실거래 API와 맥북 M3에서의 장시간 운영은 검증하지 않았습니다. 모의 체결은 기존처럼 수수료·슬리피지 없이
입력 가격에 즉시 체결합니다. 실거래 체결 경로는 가짜 브로커로만 검증했습니다.
