# 개발 로드맵

대화 이력 없이도 다음 작업을 판단할 수 있도록 단계별 완료 조건, 차단 조건, 선행 작업을 정리합니다.
이 문서는 작업을 자동으로 예약하거나 실행하는 설정이 아닙니다. 진행률을 숫자로 표시하지 않으며, 미래 수익을 약속하지 않습니다. 실제 계좌·잔고·체결·기기 경로·운영 로그는 이 문서에 옮기지 않습니다.

2026-11-06 개정: 전략 검증을 실시간 전방 창 대기 대신 **다년치 과거 데이터 walk-forward 우선**으로 바꾸고, 운영 검증을 전략 검증과 분리했습니다. 불변 원칙([AGENTS.md](../AGENTS.md), [PROJECT_INVARIANTS](PROJECT_INVARIANTS.md))은 바뀌지 않았습니다. 아래 일정은 추정이며, 관문을 못 넘으면 뒤 단계가 그만큼 밀립니다.

## 진행 원칙

새 이슈를 만들거나 고를 때 아래 원칙을 따릅니다.

- **과거 데이터 먼저, 실시간은 확인용.** 전략의 가치는 다년치 과거 데이터의 사전 고정 walk-forward로 판정합니다. 실시간 PAPER는 운영 안정성 검증(Phase 3)과 최종 후보의 짧은 전방 확인(Phase 5)에만 씁니다.
- **운영 검증과 전략 검증 분리.** 장애·복구·원장 대사는 전략 성과와 무관하므로 전략 후보를 기다리지 않고 기존 Legacy로 병행 검증합니다.
- **사전등록 템플릿화.** 새 평가는 공통 러너 하나와 protocol 파일로 등록합니다. 평가마다 새 러너와 파일별 해시 목록을 만들지 않습니다(P35).
- **커밋 고정 실행.** 평가 코드는 protocol에 적은 git 커밋으로 고정하고 임시 worktree에서 실행합니다. 이후 코드 변경이 기존 평가를 깨지 않습니다(P35).
- **운영 주기도 연구 대상.** 1분봉 운영을 전제로 두지 않고 1/15/60분봉을 같은 틀에서 비교합니다.
- **한 이슈 = 한 판단.** 이슈 본문에 "이 이슈가 낳을 판단"(진행·보류·중단 중 무엇을 정하는지)을 적습니다. 순수 인프라 이슈는 다음 판단에 필요할 때만 엽니다.
- **과최적화 방지는 유지.** 분할·비용·판정 규칙은 데이터를 보기 전에 등록하고, 최종 holdout은 한 번만 쓰며, 결과를 본 뒤 파라미터·기간을 재탐색하지 않습니다.

## 작업 흐름

1. 리뷰어(Claude 또는 ChatGPT)가 이 로드맵에 따라 다음 이슈를 만듭니다. 이슈 첫 줄의 `AUTO_TRADE_READY_FOR_CLAUDE`와 `Dedup-Key`는 구현 착수 가능 표시입니다.
2. Claude Code가 이슈를 구현하고 PR을 올립니다.
3. 리뷰어가 PR을 검토·병합하고, 결과에 따라 이 로드맵을 갱신한 뒤 다음 이슈를 만듭니다.

## 이전 단계 기록 (P22~P33)

- **P22 고정 전방 평가:** UTC [2026-11-03, 2026-11-06), BTC/XRP, 비용 5/5/2bps, 44bps 진입 필터. P25 이후로는 `tools/p22_isolated.py`로만 실행합니다. 결과 검토 뒤 **44bps 필터의 운영 채택은 보류**했습니다(영구 기각 아님). P22의 상태·파일·등록 해시는 변경하지 않았습니다.
- **P31 (#65, PR #66):** `python -m ops.research_run p22`가 수집 → 격리 평가 → 조건부 보조 감사를 각각 1회 실행합니다.
- **P32 (#67):** 기존 `ConsensusStrategy(2)`를 P19 개발 자료에서 Legacy·44bps와 비교했습니다. 개발 표본 결과일 뿐 독립 검증이 아닙니다.
- **P33 (#69, 등록 PR #72):** Consensus 2/3 전방 평가가 UTC [2026-11-08, 2026-11-15)로 등록됐습니다. 후보는 계속 운영 보류입니다.
- **판단 원칙(유지):** 결과에 따라 보류·기각·추가 검증 중 하나로 정합니다. 나쁜 결과에도 임계값·기간을 재탐색하지 않고, NO_TRADES는 개선으로 보지 않으며, 현금·BH40 대비 손실을 그대로 보고합니다.

## 단계별 계획

### Phase 0 — P33 마무리와 기반 정리 (~ 2026-11 말)

- 2026-11-15 00:00 UTC 이후 사용자가 P33 수집·분석을 수동으로 1회 실행하고, 리뷰어가 판정을 기록합니다. 재수집·기간 변경은 없습니다.
- 공통 사전등록 러너와 커밋 고정 실행 — [#75](https://github.com/sasumpi123/auto_trade/issues/75) (P35)
- 다년치 과거 데이터 스냅샷 수집과 품질 보고 — [#76](https://github.com/sasumpi123/auto_trade/issues/76) (P36)
- README를 실제 구조·명령에 맞게 정리 — [#77](https://github.com/sasumpi123/auto_trade/issues/77) (P37)
- 기존 HALTED 계좌 3개는 계속 보존합니다. 보관 방식 변경은 사용자 결정 사항입니다.
- **관문:** 공통 러너가 P33 결과를 그대로 재현하고, 과거 데이터 스냅샷이 품질 검사를 통과함.

### Phase 1 — 과거 데이터 walk-forward 검증 (2026-11 말 ~ 2027-01 중순)

실시간 3~7일 창은 거래가 드문 전략에 표본이 너무 작습니다. 다년치 자료는 2018년 하락장, 2021년 상승장, 2022년 급락장 등 여러 국면을 담고 있습니다.

- **선행:** P35, P36 병합.
- 최근 6개월은 최종 holdout으로 봉인하고, 그 이전을 연 단위 fold(과거 구간으로 정하고 다음 1년으로 검증)로 나눕니다. 분할·비용·판정 규칙은 데이터를 보기 전에 P35 protocol로 등록합니다.
- 소수 후보(예: Consensus 2/3, RSI, Bollinger, Legacy)를 1/15/60분 주기로 비교합니다. 파라미터는 개발 fold 안에서만 정합니다.
- P17 비용, P29 현금·BH40, P28 가상 청산을 그대로 쓰고, fold별·국면별·종목별 성과와 거래 수를 함께 보고합니다.
- 다음 봉 시가 체결, 전량 체결 가정, 결측 봉 격리를 유지합니다. 상장폐지 종목이 빠진 생존 편향은 해석에 명시합니다.
- 최종 후보를 고른 뒤 최근 6개월 holdout과 2026-10-21 스냅샷의 봉인 구간에서 한 번만 평가합니다.
- **관문(제안):** 한 후보가 검증 fold 과반과 holdout에서 비용 차감 후 현금·BH40을 함께 초과하고, 성과가 특정 종목·기간에 몰리지 않음.
- **중단:** 모든 후보가 실패하면 지표 신호 체계를 재검토합니다. 그동안 기본값은 현금 대기입니다.

### Phase 2 — 계좌 단위 위험 관리 (Phase 1과 병행, 2026-12 ~ 2027-01 중순)

- 진행 중: P34 (#73, PR #74) 한 계좌 두 종목 동시 하락 시 현금·노출·물타기·손절 경로 실측.
- 총노출 상한, 일·주간 손실 한도 도달 시 신규 진입 중지, 연속 손실 시 HALT와 수동 재개를 설계합니다.
- 물타기 정책을 재평가합니다. 운영 정책 변경은 사용자 승인이 필요한 전략 변경입니다.
- 백테스트와 PAPER가 같은 위험 모듈을 쓰게 합니다.
- **관문:** 합성 시나리오에서 한도 발동·중지·재개가 원장과 일치하고, 백테스트로 MDD 영향이 측정됨.

### Phase 3 — 운영 검증용 장시간 PAPER (2026-12 ~ 2027-01, 전략과 분리)

- 1단계: 3,600초 상한 안에서 세션 연결로 누적 8시간 — [#78](https://github.com/sasumpi123/auto_trade/issues/78) (P38)
- 이후 24시간 → 7일로 늘립니다. 실행 상한 변경이 필요하면 범위를 특정해 사용자 승인을 받습니다.
- 네트워크 단절, 프로세스 강제 종료, 노트북 슬립, 시계 오차, 스트림 공백을 주입합니다.
- 전략은 Legacy로 시작하고 Phase 2 한도가 준비되면 결합합니다.
- **관문:** 7일 PAPER에서 중복 주문 0건, 현금·수량·수수료가 원장과 일치, 모든 HALT의 원인이 분류됨.

### Phase 4 — 적응 레이어 (2027-01 ~ 2027-02, 과거 데이터로)

- 변동성·추세 강도·거래량처럼 판단 시점에 알 수 있는 특징만으로 국면을 나눕니다. 결과를 본 뒤 붙인 국면 이름은 쓰지 않습니다.
- 후보별 국면 성과로 배분 규칙(현금 포함)을 만들고, 전환 비용을 포함해 단순 고정 전략과 비교합니다.
- Phase 1 생존 후보가 1개뿐이면 "단일 전략 + 현금 on/off" 규칙으로 축소합니다.
- **관문:** Phase 1과 같은 fold와 봉인 holdout에서 적응 규칙이 고정 전략과 현금을 비용 차감 후 넘음.

### Phase 5 — 최종 후보 전방 확인 PAPER (2027-02 ~ 2027-03 중순)

- Phase 1·4를 통과한 최종 규칙 하나를 사전등록하고 4주간 실시간 공개 시세로 PAPER 운용합니다. 목적은 재현 확인이지 새 탐색이 아닙니다.
- 과거 백테스트 대비 체결 가격·비용·신호 빈도 차이를 측정합니다.
- **관문:** 성과가 과거 검증 범위 안에 있고, 현금·BH40 대비 결과를 그대로 보고함.

### Phase 6 — 실거래 준비와 소액 파일럿 (2027-03 중순 이후, 승인 시)

- 실주문 경로(생성·조회·취소, 부분 체결, 호가 단위·최소 주문, 응답 유실 시 거래소 조회로 상태 확정)와 거래소 잔고·원장 대사 도구를 만듭니다.
- 충분한 수익·위험 증거와 사용자의 별도 명시 승인(금액·한도)이 모두 있어야 4주 소액 운용을 합니다. 한도 초과 시 중단합니다.
- **관문:** 파일럿 기간 원장 불일치 0건, 실제 비용이 PAPER 가정 범위 안.

## 실거래 전환 없음 (유지)

- 위 Phase 6 승인 전에는 `REAL_TRADING=False`를 유지합니다.
- 추가 지출은 0원입니다. 유료 API·모델·인프라는 쓰지 않습니다.
- Slack, launchd, 무인 실행, 자동 병합은 계속 꺼 둡니다.
