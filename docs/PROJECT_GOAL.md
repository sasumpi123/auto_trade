# auto_trade의 목표와 완료 기준

**업비트 원화 현물 시장에서, 판단 시점에 알 수 있는 정보로 거래 전략·투자 비중·현금 대기를 선택하고, 정해 둔 위험 한도 안에서 비용 차감 후 자산을 장기적으로 늘릴 수 있는지 검증하고 운용하는 시스템을 만든다.**

연구·PAPER의 기준 시작 자금은 100만 원이다. 수익률 목표치, 허용 손실액, 실거래 투입 금액은 이 문서에서 정하지 않는다. 구체적인 실험과 승인 상태는 [개발 로드맵](ROADMAP.md)과 해당 이슈에서 확인한다.

## 시장에 적응하는 두 가지 방법

- **운용 중 선택** — 추세 추종, 평균 회귀, 지표 합의 등은 검토할 가설이다. 후보별로 유리하거나 불리한 조건을 조사한 뒤, 그 시점까지 관측된 시세만으로 어느 전략에 얼마를 배분할지 정한다. 근거가 약하거나 비용·위험이 크면 현금 보유도 선택할 수 있다. 시장 상태 분류, 전환 시점, 비중 조절을 합친 규칙도 하나의 전략으로 평가한다. 전환할 때 발생하는 비용까지 포함해 가장 단순한 고정 전략과 비교한다.
- **검증 후 개선** — 실험마다 가설·기간·종목·비용·위험 한도·판정 기준과 버전을 먼저 기록한다. 실험 도중에는 그 규칙을 고정한다. 성과 악화가 신호, 시장 변화, 체결 비용, 데이터 또는 운영 문제 중 무엇과 관련되는지 확인하고, 개선안은 별도 버전으로 검증한다. 검증된 버전만 승격하고 중단·복귀 조건도 함께 정한다.

## 무엇을 증명해야 완성인가

| 단계 | 판단에 필요한 증거 |
|---|---|
| 전략의 가치 | 개발에 쓴 자료와 시간상 분리된 새 표본에서 여러 시장 조건을 평가한다. 동일한 창과 자금 기준으로 수수료·슬리피지·스프레드를 차감한 성과를 현금 100%, 매수보유 40%(BH40), 고정 전략과 비교한다. 최대 낙폭, 거래 수, 보유 비중, 성과의 종목·기간 편중을 함께 본다. |
| 적응의 가치 | 개별 후보와 전략 선택·비중 전환 규칙을 각각 평가한다. 결과를 본 뒤 붙인 시장 국면 이름을 과거의 매매 판단에 쓰지 않는다. 무거래·누락·미완료 건수를 공개하고, 종가 평가·모델상 청산·확정 체결을 구분한다. 근거가 약하면 후보를 보류하거나 기각한다. |
| 자본과 운영의 보호 | 종목·계좌 총노출, 추가매수, 허용 손실, 중단·수동 재개 조건을 사전에 정한다. 감독하 장시간 PAPER에서 시세 중단, 주문 상태 불명, 프로세스 종료를 겪어도 중복 주문을 막고 현금·수량·수수료를 원장과 대사할 수 있어야 한다. |
| 실제 운용과 개선 | 충분한 수익·위험·운영 증거를 검토한 뒤 사용자가 금액과 한도를 명시적으로 승인해야 소액 실거래를 검토한다. 거래소 체결과 원장의 차이, PAPER 대비 실제 비용 및 손실을 추적하고 한도 초과 시 중단한다. 새 버전도 같은 검증 절차를 거친다. |

## 지금의 작업 경계

2026-11-06 기준 PAPER 거래·회계와 비용 반영 연구 경로를 구현했다. 고정 44bps 후보는 운영 채택 보류, Consensus 2/3는 연구 후보이며 다음 전방 평가 제안은 [이슈 #69](https://github.com/sasumpi123/auto_trade/issues/69)에서 다룬다. 시장 국면별 자동 전환과 비중 배분은 향후 검증할 목표다.

현재 모드는 `REAL_TRADING=False`이고 추가 지출 한도는 0원이다. 기존 계좌·HALTED 원장·백업을 보존한다. 유료 API·모델·서버 사용, Slack 발신, launchd·무인 실행, 자동 병합은 비활성이다. 실제 주문·배포에는 별도 명시적 승인이 필요하다. 상세 규칙은 [프로젝트 불변 원칙](PROJECT_INVARIANTS.md)을 따른다.

## AI가 다음 작업을 고르는 법

이슈·PR에는 **이번 변경으로 어떤 매매 또는 운영 판단을 더 잘 내릴 수 있는지**, **어떤 증거가 나오면 진행·보류·중단할지**를 적는다. 기존 자료와 도구로 답할 수 있으면 먼저 재사용한다. CI와 합성 테스트는 구현의 근거로, 실제 공개시세 PAPER와 비용 반영 전방 평가는 각각 운영과 전략의 근거로 구분한다. 같은 구간에서 가장 잘 나온 조합이나 한 번의 수익만으로 운영 기본값을 바꾸지 않는다.
